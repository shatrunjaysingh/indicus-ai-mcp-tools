Battery Warranty Analytics Demo

Three AI agents that read a battery maker's warranty data and find where money is lost: healthy batteries replaced, a manufacturing batch failing early, and claim fraud. Each agent also handles a counter-case that looks like the same problem and isn't. This page has the dataset, the setup and the questions to ask.

Questions to ask

Start a New chat for every question, so an earlier answer cannot steer the next. Amber questions are traps: a careless agent gives the wrong answer. Each costs roughly ₹3–16 in model use.

No-Fault-Found Analyst

finding

Why is our warranty cost high?

Overall 10.0% (342 of 3,428), ₹21.28 lakh. Pune 31.2% is the outlier; TEC-PUN-009 (59 of 82) and TEC-PUN-004 (61 of 91) replace without a load test. Recommends a mandatory load test and coaching. Must not call anyone dishonest.

trap

Is Jaipur a no-fault-found problem? Claims there jumped this summer.

No. Jaipur's rate is 3.2%, near zero in May and June; load tests failed, factory found heat damage. Wrong: "more claims means more giveaways".

finding

Was the replacement in CLM-PUN-24601 justified?

No. OCV 12.58 V, no load test, no alternator check, healthy cells; the factory found no fault.

trap

Was the replacement in CLM-JAI-31877 justified?

Yes. OCV 11.62 V, load test failed, low cells; the factory found grid corrosion.

trap

How does technician TEC-PUN-003 compare with TEC-PUN-004?

TEC-PUN-003 load-tests 88% of jobs and has 3.6% healthy replacements: the problem is two technicians' practice, not Pune.

Batch Quality Watch

finding

Is any batch failing early?

A2-2603-2: 26 of 146 within six months, 178 per 1,000 (95%: 125–248) against a median of 7.5. Cell 3 short, sold across many cities, separator lot SEP-2603-09 and a formation excursion; A2-2603-1 shares the lot. Cause stated as likely. Recommends holding stock.

trap

H1-2201-1 has more claims than any other batch. Is it bad?

No. 390 units, made Jan 2022: claims come from size and age, late in life; early-failure rate ~2.6 per 1,000, below the median.

trap

Is the Ahmednagar plant or line 2 the problem?

No. Line A2 runs at 10.0 per 1,000 against ~8 elsewhere: one batch, not the line or plant.

finding

Battery EX-A2-2603-2-00001: should we worry about it?

Reads the batch from the serial and says the unit is in the affected batch.

Warranty Fraud Review

finding

Which dealers should we audit?

DLR-NGP-021 first, with four signals: replacement rate, 60% healthy at retest, 31% in the last 10 days of warranty, TEC-NGP-007. The reused photo. Risk and audits, never guilt.

trap

DLR-JAI-012 approves 84% of claims. Is it suspicious?

No. Only 1 of 42 retested batteries was healthy: Jaipur heat failures are real.

finding

Is phone +919820155443 suspicious?

High risk: 6 batteries at 3 Mumbai dealers in two months, not the registered owner, 4 of 6 healthy at retest.

trap

Is phone +919822077110 suspicious? It has claimed on 9 batteries.

No. Sai Cabs, a registered fleet that owns all nine; every retest was a real fault.

finding

Are any label photos being reused?

One photo on three claims for three different batteries: two at DLR-NGP-021, one at DLR-NGP-018.

What a good answer looks like

  • Every rate comes with its count: "72%, 59 of 82".
  • It checks the innocent explanation before naming a problem.
  • It recommends audits, coaching or process changes, and never accuses a person.
  • It leads with the answer, then the evidence, then what to do.

Checked on 18 Oct 2026: four questions, including three traps, all answered correctly, for about $0.36 in total.

Running it

On the demo laptop (today)

  1. Start the platform, and the web app with npm run dev in frontend (port 5173).
  2. Start the demo tools on the platform's network: in indicus-ai-mcp-tools, PLATFORM_NETWORK=agentic-platform_default docker compose up -d --build.
  3. Allow the platform to reach them: Settings → Deployment → egress_private_hosts = mcp-tools.
  4. Run docker compose exec mcp-tools python seeds/battery.py. A new workspace stops at "No usable model": add the Anthropic key in that workspace and run it again.
  5. Sign in, switch to Battery Warranty Analytics, open Tasks.

On indicus-ai.com (after the 22 Oct Exide demo)

  • Run only the battery service on the production server, not the whole demo service: the server is small and serves live clients.
  • Change the seed to sign in with the owner's own account rather than the demo login, which has a known password.
  • Set egress_private_hosts, run the seed, add the Anthropic key in the new workspace.
  • Only the workspace, tool definitions, skills and agents go into production's database. No battery data.
